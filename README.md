# 팜가디언 문서

**2026-10-27 갱신.** DB 스키마 확정(16테이블·Supabase)과 API 계약 전면 재작성을 반영했다. 쓰지 않는 문서는 지웠다.

정본은 셋이다 — **스키마**는 DB 시드 전달서, **계약**은 api-spec, **제품 동작**은 요구사항 명세서. 어느 것도 다른 문서에 복제하지 않는다.

## 팀원에게 먼저 공유할 문서

1. [PRD](docs/shared/팜가디언_PRD.md): 서비스의 목적·사용 흐름·기능 범위·우선순위.
2. [요구사항 명세서](docs/shared/팜가디언_요구사항명세서.md): 기능별 동작·예외·완료 조건·공통 규칙.
3. [페르소나](docs/shared/팜가디언_페르소나.md): 네 사용자의 상황·목표·겪고 있는 어려움·사용 순서.

요구사항 명세서는 기능 25개·비기능 8개다. 기능을 개별 구현·동작 확인 단위로 나눈 표는 39행이며, 같은 FR ID에 여러 기능 행이 연결될 수 있다. FR-303은 공통 판정 기준, FR-304는 결과 목록 표시다.

위 문서는 현재 팀 검토용 문서다. 미확정 항목은 팀 합의가 끝난 요구사항으로 간주하지 않는다.

## 검토·개발 자료

- [프로젝트 현황](docs/internal/프로젝트_현황.md): 세션 인계·기존 결정·진행 상황. 기술·역할·일정은 담당 검토가 필요하다.
- [제품 쟁점](docs/internal/팜가디언_제품쟁점.md): PM의 선택안과 팀 확인이 필요한 내용.
- **[DB 시드 전달서](docs/technical/DB_시드_전달서.md)** (2026-10-15): 16테이블 ERD·마이그레이션·RLS·③ 횟수 계산·첫 사례 시드·미확정 18건. **DB 구조의 유일한 기준.**
- **[API 목록](docs/technical/API_목록.csv)** (2026-10-26): 엔드포인트 36개. **경로의 유일한 기준.**
- **[api-spec.md](docs/technical/api-spec.md)** (2026-10-27 전면 재작성): 엔드포인트 36개 요청·응답, 공통 타입, 에러 11종, 하드 룰 11, 데모 목 케이스 6. **FE↔BE 계약의 유일한 기준.**
- [테크스펙](docs/technical/팜가디언_테크스펙.md): 아키텍처·설계 결정·`route` 정규화·judge() 계약·외부 연동·배치·테스트 전략. 스키마와 계약은 복제하지 않고 위 두 문서를 가리킨다.
- [Mermaid 도식](docs/diagrams/README.md): 사용자 흐름·판정 흐름·기능 구조·데이터 개념도. `.mmd` 파일이 정본이다.
- [수집 데이터 안내](data/README.md): 수집한 원본 엑셀과 팀원이 작성한 자료 설명.
- **[FE 화면 시안](app/README.md)** (2026-10-30): 화면 9개. 판정 로직은 `app/src/lib/verdict.ts`, 디자인 토큰은 `app/src/index.css`. 서버는 아직 안 붙였고 `app/src/data/mock.ts`로 돈다. 추가로 필요한 API는 [app/docs/api-wanted.md](app/docs/api-wanted.md).
- 아카이브(`archive/`)는 이전 기획·회의·시연 자료다. gitignore로 레포에 올리지 않는다.

제품 범위·우선순위는 PRD, 상세 동작·검증 조건은 요구사항 명세서, **스키마는 DB 시드 전달서, API 계약은 api-spec**을 따른다. 노션의 최신 편집 내용은 사용자가 관리하며 자동 동기화하지 않는다.
